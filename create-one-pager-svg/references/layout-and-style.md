# レイアウトと視覚スタイル

## レイアウト選択

### dense-modules

既定。記事、議事録、政策資料など、複数論点を中間粒度で読ませる場合に使う。主役を最大面積にし、周辺モジュールを均等にしない。

### central-orbit

中心概念と5〜7個の周辺要素の関係を伝える場合に使う。循環または相互作用が実際にある場合だけ円形矢印を使う。

### process-architecture

上段に処理フロー、下段にシステム構成や実装基盤を置く。技術記事、AgentOps、AWS構成に向く。

### argument-map

問題提起、根拠、反論、条件、結論を整理する。論説、研究、政策、会議の論点整理に向く。

### comparison

2〜4案の違いが中心の場合に使う。共通評価軸を揃え、単なるカードの羅列にしない。

## スタイル選択

### editorial-knowledge-map

既定。記事、会議録、研究、政策を「一目で主張が分かり、読めば内容まで理解できる」知識ポスターへする。白地に濃紺の強いタイトル、色分けしたセクション帯、白い説明カード、太めの日本語ゴシック、線画アイコンを使う。詳細は `editorial-knowledge-map.md` を参照する。

### editorial-research

より静かで文章中心の表現が必要な、人文、研究、政策、解説記事向け。

- 明るい紙色の背景
- 濃紺または墨色の本文
- 落ち着いた青緑、金、朱を限定的なアクセントにする
- 細い罫線、余白、タイポグラフィを重視する
- 工業図面風の座標、過剰なグリッド、管理番号を避ける

### corporate-executive

経営層向け。白、青、グレーを基本にし、結論、数値、意思決定事項を強調する。装飾は少なくする。

### blueprint-technical

AWSアーキテクチャ、AgentOps、データフロー向け。暗色背景または淡い設計図背景を使い、コンポーネント境界と接続関係を明確にする。

### minimal-data

数値、比較、推移が主役の場合に使う。チャート面積を確保し、説明カードを減らす。

## 視覚階層

- タイトル: 誌面幅の70〜100%、最初の3秒で主題が分かる表現
- core message: タイトルとは別に、変化または結論を1文で示す
- main module: 誌面の25〜45%
- important module: mainの40〜70%
- supporting module: mainの25〜50%
- footer: 読める最小サイズを守り、出典と凡例を置く

## 密度の目安

1600×1000の場合：

- タイトル: 42〜58px
- セクション見出し: 21〜28px
- 本文: 16〜20px
- 注記: 12〜14px
- 全本文量: 日本語650〜1,200文字を目安とする
- 1行: 日本語15〜28文字を目安とする

`editorial-knowledge-map` ではタイトル52〜68px、セクション見出し24〜32px、本文15〜19pxを使い、細い文字を避ける。

## 禁止事項

- すべての箱を同じサイズ・同じ濃度にする
- 長文をそのままカードへ流し込む
- 関係のない装飾矢印を加える
- アイコンだけで抽象概念を説明する
- 低コントラストの薄いグレー文字を多用する
- 人物や製品のロゴを根拠なく生成する
