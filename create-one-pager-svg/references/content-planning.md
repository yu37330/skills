# 内容分析と情報圧縮

## 目的

原文を短くするのではなく、1枚で理解するための論理構造へ変換する。

## Content Structure

`content-structure.json` は次の構造を基本とする。

```json
{
  "document": {
    "title": "原題",
    "source": "ファイル名またはURL",
    "document_type": "article",
    "language": "ja"
  },
  "summary": "原文全体を2〜4文で説明",
  "message_candidates": [
    {
      "message": "中心メッセージ候補",
      "reader_value": "対象読者にとっての価値",
      "supporting_evidence_ids": ["E01", "E02"]
    }
  ],
  "narrative_candidates": [
    {
      "archetype": "possibility-core-guardrails",
      "reason": "可能性と守るべきものを、協働構造によって統合できる",
      "theme_ids": ["T01", "T02"]
    }
  ],
  "tensions": [
    {
      "left": "効率化・探索範囲の拡大",
      "right": "原資料・問い・人間の解釈",
      "resolution": "AIと人間の役割を分けた協働"
    }
  ],
  "themes": [
    {
      "id": "T01",
      "role": "mechanism",
      "heading": "テーマ名",
      "explanation": "意味を保った短い説明",
      "importance": 5,
      "evidence_ids": ["E01"]
    }
  ],
  "entities": [],
  "relations": [],
  "evidence": [
    {
      "id": "E01",
      "type": "fact",
      "claim": "図に使用できる記述",
      "source_location": "見出し名または段落番号",
      "source_excerpt": "照合に必要な最小限の原文",
      "confidence": "high"
    }
  ],
  "gaps_and_cautions": []
}
```

## Evidence Type

- `fact`: 原文に明記されている事実、数値、引用可能な主張
- `consensus`: 複数箇所を統合して得た共通認識
- `insight`: 原文を根拠に作成者が導いた示唆
- `caution`: 制約、反証、条件、不確実性

図中の表示はそれぞれ「事実」「共通認識」「示唆」「留意点」とする。

## 圧縮ルール

- 中心メッセージは1文、原則45〜90文字とする。
- モジュールは原則5〜7個とする。
- 1モジュールは見出し1つ、要約1つ、補助要素1〜4個とする。
- 同じ意味の説明は統合する。
- 原文の章立てより、因果・対比・階層・循環など内容の関係を優先する。
- 数値は意味が変わらない範囲で単位を統一する。
- 重要な例外や制約を、見栄えのために削除しない。

## 物語の型

原文の章順ではなく、読者が理解しやすい型を1つ選ぶ。

### possibility-core-guardrails

可能性と懸念が同時に語られる記事、会議録、研究・政策資料に使う。

1. 何が可能になるか
2. 中心となる人間・AI・組織の協働構造は何か
3. 何を失ってはいけないか
4. そこからどんな新しい問いが生まれるか
5. 実践を支える原則は何か
6. 最後に何を目指すのか

「効率化」だけを価値として扱わない。原資料、問いを立てる力、人間の判断、責任、熟考の時間など、原文が非効率に見えても守ろうとしているものを抽出する。

### problem-mechanism-outcome

課題、仕組み、結果が中心の技術記事に使う。課題と結果を直接つながず、中心に実装・運用の仕組みを置く。

### lifecycle-pillars-roadmap

運用モデルやガイドラインに使う。ライフサイクル、支柱となる原則、導入順序を分ける。

## 中心メッセージの選定基準

候補ごとに次を内部評価する。

1. 原文全体を代表しているか
2. 対象読者が知る価値があるか
3. 5〜7モジュールで根拠を示せるか
4. 単なるテーマ名ではなく、変化や関係を表しているか
5. 原文の事実から逸脱していないか
6. 効率や効果だけでなく、条件・責任・守るべき価値まで含むか
