# 描画準備の完了判定

この判定は「描画前レビューへ進める」ことだけを意味する。自動的なJSON・SVG生成を許可しない。資料生成には、仮まとめを見たユーザーからの明示的な作成確認が別途必要である。

次をすべて満たしたら質問を止め、描画前レビューへ進む。

- 何を決める相談かを一文で言える。
- 解くべき中心課題、症状、主要な根本要因を区別できる。
- 根本要因を支持する観察事実、または未確認であることを示せる。
- 主要な価値衝突か、手放してはいけない判断・責任境界を説明できる。
- 推奨方向と、少なくとも一つの代替案を比較できる。
- 少なくとも2件の方向候補について、解決すること・解決しないこと・前提・リスクを比較できる。
- 推奨方向が、具体的な役割・行動・期待成果として説明されている。
- 推奨方向で活用する経験・強み・資産と、その根拠がある。根拠がない場合は未確認と示されている。
- 推奨の根拠と成立条件を説明できる。
- 推奨方向が誤りだと判断する反証条件、または撤退・見直し条件がある。
- 数値を判断条件に使う場合、指標の単位、分母、判定方法、現状値との比較可能性が確認されている。未確認なら仮の閾値と表示されている。
- 高リスク領域では、平均指標とは別に重大事象の停止条件がある。
- 継続、変更、停止または後回しを区別できる。
- 直近1〜4件の行動に、比較対象と完了条件がある。
- 残る未解決事項を明記できる。
- 描画前確認へ、成果物に入れる前提・数値・行動・実施主体・承認条件がすべて含まれている。
- 一つの論点カードへ異なる証拠種別を混在させず、事実・認識・予測・仮説・未確認をカード単位で分けられる。
- 重要度の高い`ready`または`active`分岐が残っていない。残る分岐は`deferred`、`out_of_scope`、`revisit_required`として理由と再検討条件がある。

対象、テーマ、工程を選んだだけでは完了としない。ユーザーが即時出力を求めない限り、資料または回答から最低でも次の4種類の情報を得る。

1. 原因とその根拠となる具体的な経験・観察
2. 価値衝突または責任境界
3. 具体的な役割・行動・期待成果を含む方向仮説
4. 反証、評価閾値、撤退条件のいずれか

将来予測だけで原因の根拠を満たしたことにしない。具体例を求めた質問に抽象的な懸念が返った場合は、懸念を仮説として保存し、観察事実は未確認のままにする。

情報が不足していても、次の条件なら出力する。

- ユーザーが不足を承知したうえで即時出力を明示的に求めた。
- 追加質問への回答が得られない。
- 仮説を明記すれば、安全に次の検証へ進める。

追加回答が得られないことだけでは描画を開始しない。不足項目を会話上で提示し、提案版を作るか確認する。作成確認が得られた場合だけ、ステータスを「提案」とし、中心となる仮説、検証方法、見直し条件を1枚絵へ含める。推奨を「確定」と表示しない。

`explore`で開始した場合は、ゴール、現状・履歴、価値基準、制約のうち、方向性を変える重要項目が空欄のままでは完了しない。`decide`で開始した場合は、提供済み資料を回答と同等に扱い、既知情報を確認するためだけの質問をしない。

## ステータス

- `提案`: 中心方向、期間、評価基準、撤退条件の重要部分をエージェントが補った
- `仮決定`: 中心方向と主要な検証条件をユーザーが選び、追加検証が残る
- `確定`: ユーザーが方向性を明示的に確定した

## 必須の描画ゲート

次をすべて満たすまでファイルを作らない。

- 仮まとめをテキストで提示した
- 確認済み情報、分析上の提案、未解決事項を分けた
- ユーザーが「この内容で作る」または同等の指示を明示した
- `render_confirmed: true`へ更新した

承認後に非数値表現を数値へ具体化しない。「重大事象が発生した場合」を「1件でも」とする変更も再確認対象とする。
