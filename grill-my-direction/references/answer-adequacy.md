# 回答充足ゲート

## 質問意図への適合

回答を次の4種類へ分類する。

- `direct`: 質問が求めた軸へ、判断に使える具体性で答えている
- `partial`: 求めた軸には答えているが、具体例・比較・閾値などが不足している
- `adjacent`: 重要な情報だが、質問が求めた軸とは異なる
- `unknown`: 分からない、経験がない、判断できない

`direct`だけをその層の完了とする。`partial`と`adjacent`から得た情報は捨てず、適切な状態項目へ保存する。ただし、元の質問意図は未確認のまま残す。

## 証拠種別

回答内の主張を次のように区別する。

- `observed`: 実際に起きた出来事、計測結果、具体的な作業
- `reported`: 本人・関係者の認識、好み、評価
- `forecast`: 将来起こると考えていること
- `assumption`: 分析上置いた仮定
- `unknown`: まだ分からないこと

`forecast`や`assumption`を、原因を裏付ける観察事実へ昇格させない。資料に根拠がある場合も、出典と主張を対応させる。

## 追質問

`partial`または`adjacent`の場合は、次の順で一問だけ追質問する。

1. 回答から分かったことを一文で要約する
2. 何がまだ未確認かを短く示す
3. 抽象語を、出来事・行動・数値・比較のいずれかへ変換して聞く
4. 「なければ、ない／分からないでよい」と逃げ道を示す

同じ文面を繰り返さない。二度追質問しても具体化できない場合は`unknown`として進み、成果物の未解決事項へ残す。

## 要約の忠実性

`理解`には、回答から直接確認できた内容だけを書く。意味を狭める言い換え、因果関係の追加、希望条件の補完をしない。語の定義が方向候補を変える場合は、元の表現を維持して別の質問で確認する。

分析上の解釈は次のように分離する。

```text
理解: 3年以内に海外転勤したい。
仮説: 会社からの海外駐在を想定している可能性がある（未確認）。
```

一問に複数の意図が含まれ、一部だけ回答された場合は、回答された軸だけを`direct`として保存する。他の軸は別分岐の`ready`に戻し、「前の質問へ十分答えていない」と評価しない。

## 方向仮説の成熟度

次が揃うまで、反証・撤退条件を質問しない。

- 実現したい変化
- 具体的に増減させる役割・行動
- 成果が生まれる仕組み
- 活用する経験・強み・資産
- 観察可能な期待成果

抽象的な能力名だけでは方向仮説とみなさない。成熟後に、小さな検証と見直し条件を決める。
