# Requirement Language Rules

## 使用する表現

確定要求は、主語、能力、条件、判定可能な結果を含める。

> システムは、会議終了後5分以内に、決定事項、担当者、期限、根拠発言をJSONで出力する。

## 避ける表現

- なるべく
- 適切に
- 必要に応じて
- 高精度
- 使いやすい
- リアルタイム
- 大量
- 柔軟に

使用する場合は、同じ要求内で数値条件、適用条件、測定方法を定義する。

## 禁止する未確定表現

主要要求に次を残してはならない。

- TBD
- TODO
- 未定
- 要確認
- 後で決める

未確定事項は要求本文に埋め込まず、`open_questions`へ分離する。

## 実装詳細との境界

PRDには利用者価値と必要能力を書く。次はExecutable Specまたは設計へ送る。

- APIエンドポイント
- クラス構造
- 関数名
- ライブラリ選定
- テーブル物理設計
- デプロイコマンド
